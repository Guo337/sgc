# Stratified Governed Convergence

> **让 AI 产出的知识可被信任。**
> Making AI-produced knowledge trustworthy.

本项目不是传统 RAG 路线的记忆后端。RAG 把知识切成块、向量化，按相似度捞回片段拼进上下文——它优化「取得准」，但不问取回的内容是否可信：来源、不确定与更正史在切块时丢失，知识本身没有生命周期。本项目把力气花在另一段：知识以带来源、带存疑标注、带更正链的完整条目存在，怎么读、怎么写、怎么审查并入由一套治理协议约束，AI 沿链接逐跳导航而非相似度盲捞。检索目前只有路由+全文搜索，弱于成熟 RAG，直说；换来的是每条知识可溯源、可审计、可更正——**治理的是知识的质量与演化，不只是取回的命中率**。

Clone 下来是一个 [Obsidian](https://obsidian.md) 知识库，没有服务进程，没有数据库。里面装着两样东西——一套写给 AI Agent 阅读并执行的**治理协议**（怎么读、怎么写、怎么审查并入），和这套协议两个月来成功且全程可追溯的**开发留痕**（250+ 个 Markdown 文件）。**库即产品，过程即证据**。

**但你无需带走全部 250+ 个文件。** 协议与留痕是分离的：你的 Agent 从本库复制**库无关骨架**——三份规格、字段契约、模板、11 个工具卷、数十张通用方法卡——在你自己的项目目录旁建起自己的库，装入你自己的内容，修订史从第一天属于你。本仓库的开发留痕只是这套协议被真实使用过的证据，不是你要背上的包袱。整个运行依赖只有 Obsidian 与一个只读 REST 插件（工具链另需 Python 3.11+，零第三方依赖）。

**Maturity: alpha.** 担保收敛过程**确定、诚实、可复现、可审计**；不担保每条结论正确。**正确性是研究假设**（尚待证明，用冻结的 Gold 仪器测量、由人类裁判）；**诚实性是研究基础，且已客观验证**——sha256 存证、文档↔实现对账、更正链与负面样本可追溯，第三方 clone 后可自行复算，多轮独立审计已核验属实。每条结论可溯源，每次更正留痕，每个已知缺口登记在案：这些不是形容词，是你 clone 之后可以亲手核验的文件。

开源后的下一阶段是**可见证的 Beta**：治理协议可移交——外部项目 Agent 仅凭公开文本独立建库运转，无需维护者介入排障。闸门判据（B1–B6）已经项目维护者裁决冻结并公开：[Beta 闸门判据](agents_vault/05-Governance/09-BETA-GATE.md)（含当前进度与证据指针）；达标经人类裁决后宣告。当前进度：五波工程（项目托管区/修订权契约/re-sync 同步层/CI/判据公开）已全部落地，B1/B4/B5 候选达标、第二次真实上提已验收并入；余 B2 副库真实使用样本与 B3 真实跨库升级走通，等外部自然触发，不造任务。

内部代号 TTL，中文原生，由人与 AI Agent 协作开发。

## 快速开始

**读库**（不需要装任何脚本）：

```bash
git clone https://github.com/Guo337/sgc.git
```

用 Obsidian 打开 `agents_vault/` 目录，从 `00-ROOT.md` 进入。想先看懂全貌，读[项目全景地图](agents_vault/03-Atlas/README.md)；英文读者从[术语表](GLOSSARY.md)开始。

**给你自己的项目建库**（推荐用法）：让你的 Agent 读 [AGENTS.md](AGENTS.md) 走分支 B，按[副库建库引导](agents_vault/02-Cards/副库建库引导.md)五步在你自己的工作区建库——已有外部真实工程项目仅凭公开文本走通全程（90 文件，结构校验零告警）。你自己的库就是你项目的主库；本库只在复制与经验回传时出场。

**单写者设计**：一个库同一时间由一个 Agent 写入，不支持多 Agent 并发——这是设计约束而非待修缺陷；多项目协作走副库联邦，不靠共写一库。

**跑治理工具链**（Agent 工作流，Python 3.11+，零第三方依赖）：先安装社区插件 [Local REST API with MCP](https://github.com/coddingtonbear/obsidian-local-rest-api) 并启用——这是 Agent 程序化读库的标准通道，本项目只用其 REST 面（只读），不用 MCP 面。第三方插件由用户自行审源、安装与信任，密钥不入库。工具以 Markdown 卷形式存于 `90-Meta/script-volumes/`，无常驻 .py：Agent 从 [AGENTS.md](AGENTS.md) 入口进入，自举抽取器→递归抽取全部卷→运行 doctor 闸门。完整命令见[全景地图 §5](agents_vault/03-Atlas/README.md)。

## 库里有什么

| 内容 | 位置 | 是什么 | 建你自己的库时 |
|---|---|---|---|
| 治理协议 | `01-Specs/` | 三份规格书：读取（怎么找）、写入（怎么存与更正）、治理（谁能改、怎么并入），外加字段契约 schema.yaml 与四种 Agent 角色的义务清单 | **复制**（正文不动，修订史归零） |

| 通用方法卡与模板 | `02-Cards/` `Templates/` | 数十张知识工程方法卡（含踩坑卡）+ 六类条目模板 | **按派生名单复制** |

计数为保守口径，以磁盘为准，随库增长。

## 它如何运作

核心命题：**AI 的语义收敛能被治理到可信**。可信的依据不是模型输出的确定语气，而是一套纪律：保留不确定、保留来源、保留人类裁判，不给出假的确定性。

**执行方式与常见记忆项目相反。** gbrain、basic-memory 这类项目有自己的软件引擎：检索、写入、合成由代码执行，AI 调用引擎。本项目没有自建引擎——**读协议、做语义判断、整理知识的是 AI Agent 本身**；脚本只做可机械核验的护栏（校验结构、守卫写入、对账文档与实现），不替 AI 猜语义；Obsidian 只提供链接索引和人类审阅界面。所谓"运行"，就是 AI 读懂这些文本并照做。这也是**智能体无关化**的实质：引擎是可换的 AI，契约是不变的文本——治理协议不绑定特定 Agent、宿主或模型，任何能读 Markdown 的智能体都能执行。

这有一个写明的前提：AI 的理解力会随代际提升，把语义约束交给文本会越来越成立。项目不声称当下 AI 已足够可靠——开发台账里正面与负面样本并存，AI 偏离规则的事件被逐条记录。偏离在设计之内：EFG 三原理（契约需执行者、评测需独立裁判、豁免需替代判据）预判失效形态，缺口台账显式登记无执行者的规则，更正链与校验器对账把偏移留痕并机械抓出。

**知识分三层，每层修改规则不同：**

| 层 | 内容 | 修改规则 |
|---|---|---|
| L1 情景 | 日志、更正记录 | 只增不改。错了追加一条更正回指原文——旧条目错了，本身是信息 |
| L2 语义 | 知识卡片 | 可就地演进，改动留痕；成熟度从种子到常青逐级升 |
| L3 权威 | 规格书、治理约束 | 修订须留更正记录，重大裁决归人 |

底层约束上层：日志的不可变是卡片提炼的证据基础，卡片的成熟度是规格升格的门槛。当前状态不是一份快照，而是一条可追溯的变更链。

**日常运转**：Agent 进库先认身份（维护者/使用者/建副库者/审核者），只读自己角色的义务清单——权限差异由路径承载，而非事后检查；查知识沿根入口→路标→卡片逐跳展开，指针不展开、不盲扫全库。改动走开源式流程：提交增改+申报说明→校验器闸门→审核并入，产出者不给自己判卷，终审归人。

**访问通道**：Markdown 文件是唯一权威，索引与数据库皆派生可弃。Agent 程序化读库经 Local REST API 插件的只读 HTTP 面（仅监听 127.0.0.1），读前做身份探针（REST 读到的根文件 sha256 与磁盘比对）防答错库；写入不经 REST——实测其写路径会重排 frontmatter 破坏字节保真——主走官方 `obsidian` CLI，经守卫式写入原语落盘（防重复、防覆盖、写后逐字节回读校验）。REST 是许多笔记软件共有的接口形态：[思源](https://b3log.org/siyuan/)、[Logseq](https://logseq.com) 等理论上可承载本库，但未实测，不做保证；Obsidian 是当前验证过的基座。

## 为什么这样做

**治理规则本身是知识。** 谁能写什么、怎么并入、什么绝对禁止——这些规则以自然语言写成，与知识同库同格式：可被检索、引用、更正，人可以直接读、直接审，不需要读源码。代价是没有机械拦截：执行靠 Agent 遵守文本，校验器事后对账。哪条规则没有机械执行者、维护者接受了这个漏，库里有一份显式台账。

**不确定必须保留。** 证据不足的结论必须标注存疑，冲突未解决必须保留双方，不许为了整洁把"不知道"抹成断言。记录"不知道"优先于给出无依据的"知道"。

**程序也是可审的文本。** 11 个工具的唯一源是库内 Markdown 卷（代码块+sha256），抽取出的 .py 是临时产物。文档宣称的版本与代码实际版本由校验器逐条对账，宣称漂移会被机械抓出；导航投影从边确定性重生成，验收判据是 diff=∅ 不动点——不含 LLM 参与，可复算。体量须明示：11 卷共约 8500 行 Python（sha256 全数与卷头声明一致），比治理文本还多。"轻代码"轻在权威形态——治理规则零行代码承载、程序全部卷化入图——不在体量。

**中文原生是治理选择，不是偶然。** 治理即文本的前提是人能读：中文母语者可以直接审阅治理规则、裁判知识争议、理解更正链，无需翻译层。对"人类终审"这一环节，母语文本实质降低审计成本。代价见"诚实边界"。

**知识库可以繁衍，而且没有中心。** 「主库/副库」只是复制方向上的相对称呼：你的 Agent 从本库复制骨架建起的库，就是你项目自己的主库——它离线自治，不依赖本库运行，本库停更它也照常运转。复制的条目保留上游编号以便溯源（同 fork 保留上游 commit hash），你的新建条目带自己的命名空间前缀，普适经验回传上游时经独立验收换号并入——是移交而非复制（同 Jira move issue 换项目 key）。这条回路已成功端到端走通：两轮真实试建 + 一次真实回传 + 首个外部项目纯公开文本冷启动建库全绿（样本还薄，如实说明；re-sync 同步层已落地——规格修订权契约+三方合并工具+结构校验判据，真实跨库升级走通待第二样本；多库并发回传未实测，均已登记）。

它适合谁：整个库只依赖 Obsidian 与一个只读 REST 插件，没有服务进程——**「伴工作区」形态**：在你自己的项目目录旁建一个库，让协助 Agent 带着治理过的记忆干活，库随项目走、随项目归档；**小团队的经验迁移与共享**：各成员/各项目各持一库，普适经验经独立验收回传共享，谁也不必读谁的源码就能审阅并入的规则（来自首批外部使用者的真实反馈；联邦成熟度仍在建设，如实说明）。入口：[副库建库引导](agents_vault/02-Cards/副库建库引导.md)、[上提验收流程](agents_vault/02-Cards/上提验收流程.md)。

## 与社区项目的关系

[gbrain](https://github.com/garrytan/gbrain)、[basic-memory](https://github.com/basicmachines-co/basic-memory)、[dory](https://github.com/deeflect/dory)（已归档）是同一问题域里更成熟的工程实现，源码级比对（2026-11-22，独立 Agent 执行）确认它们在检索、机械强制、评测规模上强于本项目。**但机理趋同不等于机制同构**——append-only 审计、人审并入、分层这些机理各家都有，承载结构却不同，而结构差异正是各自能做什么的分界：

| 维度 | 社区项目（软件引擎形态） | 本项目（治理文本形态） |
|---|---|---|
| 治理规则在哪 | 数据库与代码里，改规则=改代码发版 | 自然语言文本，与知识同库同格式——**使用者不读源码即可审阅、引用、更正治理规则本身** |
| 分层是什么 | 作用域划分或信任分级 | 每层**修改契约**不同的沉积式生命周期：L1 只增不改是 L2 提炼的证据基础，L2 成熟度是 L3 升格的门槛 |
| 谁执行语义 | 代码执行检索/写入/合成，AI 调用引擎 | AI 读协议自己执行，脚本只做机械护栏——**换 Agent/宿主/模型不换契约** |
| 历史账本 | 在数据库里，clone 拿不到 | 全部裁决、更正、失败归因是带指针的文本，**clone 即得全史** |
| 知识的繁衍 | 单库为中心 | 库可复制骨架繁衍，各库离线自治、经验经独立验收跨库移交 |

这张表不是「我们更强」的清单——每一行右列都有代价：文本治理没有机械拦截，强制力弱是真实的；检索、接入、压缩恢复落后是真实的。它说的是**两边不是同一赛道上做得多与少，而是结构不同的两种东西**：要一个今天就能用的记忆后端，选左边；要治理逻辑本身可被人和 Agent 审阅、要一套能移交给自己项目的知识纪律，本项目提供的是这个。

为什么不基于社区项目改？立基取向中的三条——Obsidian 原生链接层、文件唯一权威、智能体无关化——与社区基座方向性冲突，fork 任何一家都保不住这三条。也承认一段弯路：立项次日的社区调研漏掉了上述三个最强项目，约七周自研的部分能力社区当时已有更好实现；这段失误连同归因写在库内卡片里，没有删。失误是真实的，结构差异也是真实的，前者不抹掉后者。

## 诚实边界

集中说明本项目**不**提供什么：

- **不担保结论正确。** 核心假设（AI 能把零散记录收敛成可信知识）目前部分验证，实验样本小（12 个构造样本）、单一模型底座。
- **没有机械写闸门。** 治理靠 Agent 遵守文本+事后校验，开发中已多次实证会漏；漏了会留痕，但不会被实时拦下。
- **检索只有路由+全文搜索。** 语义检索、图排序、时间加权装配均未实现，库内逐项标注为"未来/未实现"。
- **治理文本仅中文。** 术语表够英文读者了解项目，不够审阅治理规则。这是"人类母语终审"定位的内在边界，不是待修缺陷。
- **压缩后恢复与会话接入弱。** session_start 生成器未接线，上下文压缩后的恢复靠文本义务而非机械机制（自认设计缺陷，已留更正记录）；社区有机械解，本项目落后。
- **公开的是过程证据，不是原始实验件。** 裁决链、更正链、hash 存证随库公开；实验原始数据与协作底稿在私有工作区（含本机路径等现场痕迹），可通过 GitHub 联系查阅。
- **无安装器、单人维护约两个月。** CI 已上线且三平台（Ubuntu/macOS/Windows）实测全绿——每次提交自动跑卷抽取 sha256 对账 + doctor 结构闸门 + 逐卷自检（[运行记录](https://github.com/Guo337/sgc/actions/workflows/doctor-gate.yml)，只读工具链，不担保语义正确）；完整体验需要 Obsidian 与一个自装的社区只读插件。

## 命名

**Stratified Governed Convergence**（SGC）：Stratified = 知识分层，沉积式底座约束上层；Governed = 治理即文本、分权、人类裁判；Convergence = 语义收敛，验证中的核心假设。内部代号 **TTL** 是立项时的双关（Time to Live + Through the Lens），与现理念关联已淡；历史文件保留不改写——只增不改的纪律，连自己的名字都不例外。改名经多轮裁断，见库内 D35 / corr-97。
