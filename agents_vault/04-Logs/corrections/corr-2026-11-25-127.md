## 改了什么

1. **SH-index 维护者路由行**：「改本库（卡/规格/工具链）」扩为「…/同步升级 re-sync」，附「库维护/同步任务也是库操作，读侧仍走 SH 通道分流」——身份分叉点即见。
2. **role-ke-maintainer 义务包**新增「同步/维护任务」行：读侧按通道分流（规格/卡/frontmatter 走 REST/CLI），字节比对与写侧落盘才是磁盘操作；指针 SPEC-GOVERN 联邦节。

4. **SPEC-GOVERN 联邦规格修订权节**首段补义务句（契约必经路径）。
5. **vol_extract v0.1.0→v0.1.1 / fed_sync v0.1.1→v0.1.2**（重封 sha 97014f7b… / bcf27c84…）：正常运行 stdout 头部输出一行 SH 提示（self-test 分支不输出，不污染自检断言）——工具是维护任务必经执行点，提示物理可达且不依赖 Agent 主动读库。

## 为什么改（原来错在哪）

- issue#4 实证（ansys 副库同步 e300934 期间）：Agent 把同步任务心智建模为「字节级文件操作」，SH/REST 义务根本不进视野——**corr-99 同根因第二触发场景**：触发端不可达有物理（压缩摘要）与心智（任务建模）两形态，后者「提示移出库」未必解决。
- 同步流程文档只描述产物与判据（卷字节原样/doctor 全绿），无一处提醒读侧分流；SH-index 维护者路由未列同步任务，身份分叉时同步无归属。
- 讽刺点（报告方指出）：该次同步升级的 rest_read v0.2.1 正是该副库报回的 REST 探针修复——一边升级 REST 工具一边不用 REST。
