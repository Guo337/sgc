## 改了什么

SPEC-READ 第 5 条（按需自启 App）两处更正：① 启动器从 `Obsidian.com` 改为 `Obsidian.exe`（Start-Process 拉起）；② 明确「探活发现 App 关时，自启是授权内首选动作，不应直接退离线；退离线须先尽自启义务」。MCP 卡同步补实测细节。

## 为什么改（原来错在哪）

- **启动器表述漂移**：旧写「自启 Obsidian.com 启动器」，实测 `Start-Process Obsidian.com` 在 PowerShell 下不拉起进程（.com 是 CLI 入口，非 GUI 启动器）；`Start-Process Obsidian.exe` 才生效。冷启动分阶段 ~25-30s。
- **自启授权被忽略**：编排方探活发现 App 关，直接退离线，**违反了已入库的 D31 自启授权**（SPEC-READ 第5条/MCP卡/corr-42 早已写明可自启）。Owner 提醒才发现。根因：prose 写了 Agent 没照做（同磁盘读 127 次）。故把「可自启」强化为「应自启，退离线须先尽自启义务」，收紧降级前置（与 corr-43 探活前置配套：探活→App关则自启→自启后仍不可用才退离线）。

## 依据

- Owner 提醒 2026-11-15（「我授权过 Agent 打开 Obsidian」）；原始授权 turn 132「可以纳入常规，仅限 Obsidian 与该目录」（2026-11-13 17:38）。
- 实测：Start-Process Obsidian.com 进程不起来；Obsidian.exe 成功（PID 3580），REST 200 + CLI 1.15.1 + MCP 端点 200。
