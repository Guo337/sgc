# corr-124：README 语体修正（口语→书面）

## 改了什么

Owner 指出 README 口语化过度。逐段修正约 30 处口语表达为书面语，**语义、事实、诚实边界、链接零改动**：

- 动词口语：捞回→检索、盲捞→按相似度检索、抓出→检出、跑→运行/执行、装→安装、干活→工作、判卷→自我验收、卡住→遇到阻碍、出场→参与、背上→构成负担；
- 短语口语：直说→如实说明、会漏/漏了→存在遗漏/遗漏、样本还薄→样本尚少、走通→验证/完成、拿不到→无法获得、保不住→无法保留、没有删→未删除、相遇虽晚学习不晚→接触虽晚借鉴不迟、照单全收→全盘照收、它适合谁→适用场景、库里有什么→库内容；
- 引号统一：残留半角 "..." 全部改「」（与全文体例一致）；踩坑卡→pitfalls 卡（schema type 术语）。

## 为什么改（原来错在哪）

README 是对外门面，语体应庄重可信；口语化表达（多为历轮快速起草时带入）削弱「治理协议」文本的严肃感，与项目「治理即文本、人可审阅」的定位不匹配——文本本身的可信度也是门面的一部分。

## 依据

- Owner 2026-11-25 指示「Readme口语化过度」。
- 修正纪律：只改语体不改语义；所有事实断言（样本数/判据状态/边界声明）逐字保留；修正后 grep 复扫口语词残留清零。
- 边界：库内治理文本（SPEC/卡）的口语词是另一套纪律（结晶质量门命名节约束卡名，正文语体未立条文），本件只动 README 门面，不扩及库内。
