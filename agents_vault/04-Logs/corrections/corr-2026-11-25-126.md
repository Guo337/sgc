# corr-126：doctor v2.18.1——上游快照硬跳过（issue Guo337/sgc#3）

## 改了什么

外部副库 ansys-automation（dingdong313）报回：doctor v2.18.0 把 `90-Meta/upstream/` 基线快照当库内容扫描，91 ERROR 全部假阳性（BROKEN_LINK ×85 上游 corr 指针 / ID_DUP ×3 快照与 copied 件同 id 是契约必然 / ID_NAMESPACE ×3 上游 id 无副库前缀）。修复：

- **entry_doctor v2.18.0→v2.18.1**（重封 sha 21b27f5e…）：
  - `HARD_SKIP` 增 `"upstream"`（inbox 先例：NON-AUTHORITY 快照工作区，不校验、不作链接目标）——磁盘扫描层生效；
  - **analyze 层同语义**（报告方建议只改 HARD_SKIP，实测不够：in-memory 调用方绕过 load_vault）：模型构建时排除硬跳过件（不进 id/标题/别名/链接图/类别聚合），原文再挂回 model.files 供 cross 规则（FED_*）读基线；dispatch 视图按 rule.scope 分流——cross 规则可见快照原文，file/link/graph 规则不可见；
  - self-test FED_RULES 增回归 fixture：raw 快照（不可解析 corr 指针+与本地 copied 件同 id）须零告警且 FED_* 正常读基线。
- 版本活链接四处同步 v2.18.1（ROOT/SPEC-GOVERN/校验清单卡/STATUS Doctor+Validation）；校验清单卡补硬跳过条目。

## 为什么改（原来错在哪）

- `90-Meta/upstream/` 是 SPEC-GOVERN 联邦 e 项的上游基线快照缓存——**非副库内容**，其上游 corr 指针/上游 id 本就不该按副库契约校验。HARD_SKIP 漏收该目录是 v2.18.0 引入 FED_* 时的配套遗漏（判据读了快照，扫描面却没排除快照）。
- 报告方根因定位准确（HARD_SKIP 不含 upstream；_fed_cache_baseline 直读磁盘不受影响），但其建议「只加 HARD_SKIP」在 in-memory analyze 路径不生效——修复须两层同语义，否则自检/程序化调用仍假报。
- 该缺陷直接打击 B3 升级路径可用性：副库按契约落快照后 doctor 全红，用户被迫容忍假 ERROR 或违规删快照。
