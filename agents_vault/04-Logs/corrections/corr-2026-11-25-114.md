# corr-114：身份探针 Windows CRLF 假阳性修复

## 改了什么

- [[rest_read]] 卷 v0.2.0→v0.2.1（重封 sha256=355c2c763a7ce323…）：`identity_probe` 磁盘侧读文件加 `newline=""`，禁 Python 通用换行转换，保原始 CRLF 字节与 REST 返回对齐；self-test 夹具同读法同步。
- self-test 增 IDENTITY_CRLF 回归例（磁盘 CRLF + REST 同字节必须 MATCH），14→15 规则全 PASS；活体探针 PASS。
- [[REST读库速查]] 助手行版本引用同步 v0.2.1、自测数 15，变更记录补条。

## 为什么改（原来错在哪）

ansys-automation 副库（Windows autocrlf 检出）重测 v2.16.0 时回报：`rest_read probe` 报 identity MISMATCH，但逐字节比对 REST 与磁盘 sha256 完全一致。根因：探针磁盘侧 `io.open(..., encoding="utf-8")` 文本模式默认通用换行，把 CRLF 静默转 LF；REST 返回原始字节保留 CRLF，两侧哈希必然不等——探针自身成了 EOL 坑族的新成员（issue 问题 3 同族，但发生在探针而非卷锚）。Windows autocrlf 副库首跑 probe 必假阳性，属真 bug 非暂态。

- 本库核实：rest_read.md L217 磁盘侧读确无 `newline=""`；修复后本库 self-test 15/15、活体探针 PASS、doctor 双模式 0E/0W/0I（278 md）。
