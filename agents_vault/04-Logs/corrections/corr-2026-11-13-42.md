## 改了什么

SPEC-READ v0.7.0 → v0.7.1，三处增补（不推翻 D30 环境分流，只补强 A.6 与访问通道）：

1. **红线 A.6 MCP 面**：原文只述 Qoder IDE「不支持配置级工具过滤、20 工具全暴露、只能 Agent 自律」。增补 **VSCode/Copilot 面**：Copilot 原生 `mcp-config.json` 的 `mcpServers.{server}.tools` 数组做**配置级硬过滤**——本机实测只把 6 只读工具递给 Agent，14 个写工具被挡在工具表外，**且子 Agent 继承同一白名单**（实测 6 只读 / 0 写）。故 A.6 的「自律红线」在 VSCode 升级为「配置级硬约束 + 自律双保险」；Qoder 仍纯自律。
2. **访问通道节**：补「MCP 注册落点」一句——Copilot harness 原生读 `~/.copilot/mcp-config.json`（`mcpServers` 格式）或工作区根 `.mcp.json`，**不直接读** `.vscode/mcp.json` / profile `mcp.json`（那是旧 Local harness `servers` 格式）；密钥用 `${ENV}` 引用不落字面。
3. **调取前置协议**：补「按需自启 App」一句——Owner 授权（仅限 Obsidian + 本目录）：REST/MCP 需 App 运行而 App 关着时，Agent 可自启 Obsidian 启动器并探活（含身份探针），用完按需留/关。

配套新增（非本 correction 直接对象，同批落地）：L2 卡 [[MCP配置级白名单与使用手感]]（c-2026-00018，配置落点 + 白名单实证 + MCP/REST 手感对比 + 编码注意点）、决策 D31（[[决策记录索引]]）、00-ROOT 路由表 D 编号范围 D1–D31。

## 为什么改（原来错在哪）

A.6 原文以 Qoder 实测概括「MCP 面只能自律」，**把单一环境的限制误写成 MCP 面的普遍属性**。本会话在 VSCode/Copilot 实测发现：Copilot 原生 `tools` 数组**支持**配置级工具过滤（Qoder 丢弃的 `includeTools` 在 Copilot 原生格式里以 `tools` 字段生效），且**子 Agent 继承**——这是官方文档未 guarantee、本机实测确认的事实。原文表述对 VSCode 环境已漂移（过窄），须增补区分，否则后续 Agent 会误以为「任何 MCP 环境都只能自律」，错失把只读白名单升级为硬约束的机会。

非推翻 D30：D30 环境分流（有 MCP 走 MCP / 无 MCP 走 REST）不变；本更正只在「有 MCP」分支内细分 Qoder（自律）vs VSCode（配置级硬过滤），并补注册落点与自启授权。
