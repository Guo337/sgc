## 改了什么

1. **doctor v2.11.0→v2.12.0**（卷代码+抽取件同步，sha 重算）：`parse_fm` 标量分支对无引号 `true`/`false` 归一为 Python 布尔（YAML 扁平子集同判）；带引号 `"false"` 保持字符串（YAML 语义亦真值）。两处 `fm.get("hub")` 消费点零改动即被根治。
2. **自检新增 BOOL_SCALAR fixture**（先红后绿）：`hub: false` 卡不得触发 HUB_*；`hub: "false"`（带引号）仍触发 HUB_GROUNDS（字符串真值，YAML 同判）；`hub: true` 解析为 True。红证明：修补前探针实测 `parse_fm('hub: false')` 返回字符串 `'false'`（真值）。
3. **schema.yaml hub 键注释更新**：corr-64 写的「勿写 hub: false」过时（当时解析器缺陷），改为布尔语义说明+惯例仍推荐省略键。**corr-64 原文不改**（append-only），本 corr 回指取代其注释建议。
4. **版本引用同步**（G20 对账 4 ERROR 全消）：00-ROOT/SPEC-GOVERN/校验清单卡/STATUS×2 → v2.12.0。
5. **2 历史文档加时点注记**（原文未改，报告批准注记同款先例）：Handoff/03-NEXT-AGENT-ENTRY.md 与 History/2026-10-01 调研档案 00-README.md——顶部注明相对链接是时点路径、目标已迁移/退役、当前入口与追溯介质。链接本身保持旧形态（不改写正文纪律）。

## 为什么改（原来错在哪）

- **布尔陷阱根因**：扁平子集解析器把所有标量存为字符串，`fm.get("hub")` 对 `"false"` 为真——与真实 YAML 语义分歧（YAML 无引号 false 是布尔假）。corr-64 只加了注释路标，但**注释不是执行者**（E 原理）：下个 Agent 写 `hub: false` 仍会踩。Owner 22:38 裁「该处理的话处理掉」→ 修解析器本体。
- **修法选择**：在 parse_fm 单点归一（而非两处消费点各加判断）——所有未来布尔字段自动受益，且与 YAML/Obsidian 同判（fail-loud 子集哲学的一致延伸：子集内的语义也要对齐真 YAML）。
- **断链注记**：丙案「不修历史」裁的是不改写正文；顶部时点注记≠篡改（原文逐字保留），与报告批准注记同款。读者顺旧链接摸到文档时一跳知道现状，补上 git 介质之外的「文档内路标」。
