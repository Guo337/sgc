## 改了什么

schema v0.6→v0.7：L1 type 枚举加 `correction`、新增 `L1_correction` 字段块、constraints 补「L3 修订说明下沉 + 底层嵌套分化」；`04-Logs/` 内部嵌套分化为 `logs/`（情景日志）+ `corrections/`（更正说明），层号不变、顶层不新增目录。三大规格 + schema 的内嵌 changelog 拆条下沉为 35 件离散 correction（本件为第 36 件，记本次变更自身），规格只留当前态 + 「修订说明（已下沉）」指针节。SPEC-WRITE 微词反馈流程「changelog 追加」改为「下沉一件 correction + 留指针」；SPEC-READ 装配预算明确 corrections 不进自动装配；SPEC-GOVERN doctor 检查项补 CORR_SECTION/CORR_TARGET/SPEC_CHANGELOG。entry_doctor 加三规则 + type 枚举 + 豁免 + self-test fixture；reflect.py scan_logs 改扫 logs/（带 legacy 回退）、append_log.py existing_log_ids 改递归（含 corrections 去重）；新增 Templates/T-correction.md；30 篇日志 git mv 迁入 logs/。

## 为什么改（原来错在哪）

原制度（SPEC-WRITE 微词反馈流程）要求每次修订「直接修订 + changelog 追加」，使三大规格各内嵌 8–10 条 changelog、占各自文件 27–29%，且病灶落在「永不裁」的 L3——只增不减的浅层堆叠阻塞 Agent 调记忆库的收敛。Owner 裁决：说明有记忆价值不删除，而是下沉到库内更深、按需才展开的位置（git 链现阶段不服务于读取收敛，故非「删除指向 git」）；粒度取 B（一次更正一件）避免聚成巨件复发；U-1 不结晶、U-2 预算漂移另立任务。
