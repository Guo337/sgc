# corr-125：反馈回路显性化——欢迎 Agent issue + 副库回馈意识

## 改了什么

Owner 指示：README 强调欢迎 Agent 提交 issue，并有意识提高副库 Agent 回馈主库的意识。三处落点：

1. **README「参与和反馈」节重写**：①明示「欢迎 Agent 直接提交 issue」——Agent 撰写反馈与人类反馈同等受理（建库报告/引导歧义/工具缺陷/治理质疑），附真实先例；②新增「副库 Agent 请有意识地回馈上游」两条：阻碍即报告（附环境/步骤/现场，直接构成 B2/B3 外部证据）、普适经验上提（链接上提验收流程）；③PR 口径精化：原「外部并入路径尚未定义」已过时（上提验收流程已定义且两次真实走通），改为「外部经验经上提验收流程并入（已有先例），其余改动先开 issue」。
2. **副库建库引导卡新增「建库后：回馈上游」节**（验证节之后、坑清单之前）：阻碍即报告 / 普适经验上提 / 使用样本三通道，各附先例（ansys issue→corr-105、c-2026-00037 上提）；明示回馈非运行依赖而是协议演化证据来源+Beta 判据自然触发。summary/changelog 同步。
3. **AGENTS.md 分支 B 补句**：issue 渠道 URL + Agent-authored reports are first-class + 上提流程指针——冷启动 Agent 在入口即见反馈义务。

## 为什么改（原来错在哪）

- 反馈义务此前只在 AGENTS.md 一句「Report where the guide is unclear」，无渠道无落点；README 参与节以人类读者口吻写，未明示 Agent 是一等反馈者——而本项目主要使用者恰是 Agent。
- 副库建库引导以「doctor 0E」为终点，未告知建库后的回馈回路——B2/B3 等待的外部样本不会自然到来，若副库 Agent 根本不知道要回馈。
- README「外部并入路径尚未定义」与事实不符：上提验收流程已定义且 vplc-001、c-2026-00037 两次真实走通（PR#2 即经此路径并入）。

## 依据

- Owner 2026-11-25 指示（欢迎 Agent issue + 提高副库回馈意识）。
- 事实锚：上提验收流程（c-2026-00022）六步已两次真实执行（corr-122）；ansys issue 报回 4 张力全属实（corr-105）；B2/B3 判据（09-BETA-GATE）等待外部自然触发。
- 边界：只加反馈引导，不改验收流程本身、不新增义务性约束（回馈是邀请非强制，与副库离线自治不冲突）；「不人为构造任务」纪律不变——本件是让自然触发可达，不是构造任务。
