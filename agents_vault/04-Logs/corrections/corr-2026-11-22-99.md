## 为什么改（原来错在哪）

- **事实链**：本会话发生上下文压缩（对话含摘要注入，结构上可检测）。压缩后首个动作=直接按摘要 next_steps 接续匿名化编辑，未走 SH-index 认身份。Owner 问「走SH了吗」才补走；Owner 追问「你意识不到你压缩会话吗」点破第二层：**不是检测不到压缩，是检测到了也没把 D34 义务挂上去**——摘要里明写 D34 纪律与「压缩后首个动作先走 SH」，仍凭摘要先验替代授权实物路由。
- **定性（Owner 2026-11-22 04:40 修正）**：初稿定性为 corr-92 同形态复发、归因 Agent 执行逸出。**Owner 修正：「你压缩完会话确实不会记得那项纪律，这是我的设计问题，放了一句废话」**——D34 的触达设计把触发提示放在库内文本（STATUS Next task 首句/ROOT L0 半句），而压缩后 Agent 的工作起点是摘要不是库；提示语「压缩后首个动作先走 SH」写给一个尚未读库的执行者，恰好在其唯一需要它的时刻不可达。触发端不可达=设计缺陷，非单纯执行违规。corr-92 当时「残余属小概率意外非漂移」的判断据此修正：残余是结构性的，概率不取决于 Agent 自觉。
- **结构缺口（登记，解法待 Owner 裁）**：D34 触达链的触发端在库内文本，压缩事件本身在库外（宿主运行时），无动作挂钩。候选结构解方向=压缩摘要注入时宿主侧强制首动作走 SH（hook 级），但 ②级 hook 已被 D32 否决，此方向是否属 D32 范围需 Owner 裁；另一方向=把触达提示移出库（写入宿主侧持久指令/AGENTS.md 等压缩不丢的载体），是否可行待裁。本 corr 只登记缺口与 Owner 归因修正，不提案升格。
