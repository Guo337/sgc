## 做了什么

1. **核实 CLI 官方性**（纯文本网页调研）：WebSearch + 抓官方源（`obsidian.md/cli`、kepano/obsidian-skills 的 `obsidian-cli/SKILL.md`、GitHub）。
2. **本机活体测试官方 CLI**：探测 PATH/安装/进程 → 用户注册 PATH + 启动 Obsidian + 打开 vault → 跑只读命令 version/search/backlinks/unresolved（零写入、未装任何东西、未用 eval）。
3. **按修正前提修缮方案 r1–r8**：设计文档（master）+ SPEC-READ/WRITE(v0.4) + schema(v0.4) + 00-ROOT + 3 种子卡 + T-card 模板 + 新建 ⚠️ 卡。

## 结论与产出

- **CLI 官方性**[P]：官方命令是 `obsidian`（Obsidian 1.12+ 自带，第一方，经 IPC 连运行中的 App）；第三方 `obsidian-cli`（yakitrak，已改名 notesmd-cli，社区品）是另一个东西；kepano/obsidian-skills 的 `obsidian-cli` skill 包的是**官方** CLI。
- **本机实测**（Obsidian v1.13.7）：`version`=1.13.7；`search query="PPR"` 命中 3 文件；**`backlinks file="HippoRAG检索机制"` 返回 GraphRAG + SH**；`unresolved` 标出 `90-Meta/MAP.yaml`、`03-Atlas/`。
- **命门推翻**：GraphRAG 对 HippoRAG 的唯一引用在嵌套 `e:` 对象内，却出现在 backlinks → **嵌套 wikilink 被链接引擎识别**；旧"nested 不可见"结论作废。
- **方案更正落地**：访问模型 = 官方 CLI 主通道 + Local REST API/MCP 可选增强 + Python/grep 离线兜底；边保持嵌套单轨；反链收回为 Agent 可只读消费（PPR 节点特异性恢复在线信号）；same_as→原生 aliases；新增 D23/D24、修订 D19/D20/D21；SPEC-READ/WRITE/schema 升 v0.4；新增 ⚠️ 卡 [[PIT-嵌套wikilink识别]]。

## 存疑与风险

- CLI 依赖 App 运行（IPC），App 关则主通道失效 → Python/grep 离线兜底必须保留（**尚未实现，Stage 1**）。
- Windows PowerShell 5.1 直接管道 CLI 输出中文乱码（GBK 误解码，数据未损），消费前须设 `[Console]::OutputEncoding=UTF8`；本次测试输出即有此现象。
- 嵌套字段 rel/weight 仍不可被 Bases/Dataview 查询；Stage 2 若按 rel 过滤边需补扁平副本 + lint（未实现）。
- backlinks 仅实测单个文件；`file.links`/graph view 对嵌套链接的计数**未直接实测**（推断同源，未证）。
- **未跑任何写命令**（create/append/property:set）；写入通道的 CLI 行为仅据官方文档，未活体验证。
- schema `id_format` 定义为 `{kind}-{yyyy}-{seq}`，但 T-log 模板与设计文档示例用 `log-{yyyy}-{mm}-{dd}-{seq}`——不一致，本条从模板；待统一。
