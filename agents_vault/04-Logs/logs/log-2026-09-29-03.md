## 做了什么

1. **rB1 取证（Qoder MCP 工具级过滤能力）**：查官方 MCP 参考（docs.qoder.com）确认——每个 MCP 服务器配置支持 `includeTools`（白名单，未列工具**根本不注册**）/`excludeTools`/`disabled`/`permissions.deny`（按 `mcp__<server>__<tool>` 硬拒），且 MCP 工具默认调用前需用户确认（除非 trust/auto）。用户确认 **Qoder IDE 后台即调 Qoder CLI** -> CLI 的 MCP schema 适用 IDE，消掉"CLI 文档是否适用 IDE"的存疑。结论：rB1 决策分支"能过滤 -> 只读白名单接入"成立，可做三层纵深（白名单不注册 + permissions.deny + 默认确认）。

2. **rB2 接线事实核实（只读取证，源码/配置，非记忆）**：插件 = `Local REST API with MCP` v5.3.1。从 main.js 静态提取 **20 个真实工具名**（与 b4r1 吻合）：只读类 11（search_simple/search_query/vault_read/vault_list/vault_get_document_map/tag_list/active_file_get_path/vault_read_binary/command_list/events_get_listener_url/vault_get_download_url）、危险类 9（command_execute/vault_write/vault_append/vault_patch/vault_copy/vault_delete/vault_move/vault_get_upload_url/open_file）。data.json 密钥安全读取（只打印字段名 + 非密钥值）：port=27124、insecurePort=27123、enableInsecureServer=False、enableSignedUrls=True、crypto 含独立 caCert。netstat 确认插件**仅监听 127.0.0.1:27124（loopback）**。Qoder 配置在 `~/.qoder-cn/settings.json`（非 .qoder），原无 mcpServers。

3. **落地最小权限只读接入（密钥安全、可逆）**：其一，只导出**公开 caCert** -> `~/.qoder-cn/obsidian-local-rest-api-ca.pem`（私钥绝不读/写）；其二，增量并入 mcpServers 到 `~/.qoder-cn/settings.json`（先备份、保留原 4 键、并入后校验、失败自动还原；VERIFY OK）：url=`https://127.0.0.1:27124/mcp/`、type=http、includeTools=6 只读工具、token 留占位符（用户填，我不碰）、不设 trust/alwaysAllow（保留确认层）。配置全在 agents_vault/git 之外 -> token 永不入库（守 [[PIT-插件密钥入库泄漏]]）。
