# 外部评审三层分诊法

## 定义

接收详细外部架构评审 / 代码审查时的理性分诊法：避免"全盘接受"或"盲目辩护"两个极端，把每条意见按性质分三类、分别处置。

## 核心

1. **真 bug（Real Bug）**：规格内部自相矛盾、事实错误、可验证缺陷。特征=有明确证据（如 `git check-ignore` 返回空、frontmatter 缺字段）。处置=**立即修复**，可逆文本修改优先。
2. **暂态（Staged Temporal）**：分阶段设计本就承认未实现的部分。特征=文档已标注 "Stage X+" / "planned"。处置=不视为 bug，但须确保文档**显式标记"计划中"**，避免误导。
3. **哲学分歧（Philosophy Debate）**：设计选择而非对错问题。特征=双方都有合理理由、涉治理/效率权衡。处置=**提交用户拍板**，不擅自决策。

**关键收获**：评审质量高时应逐条核实而非情绪化回应；优先级 真 bug（影响规范一致性）> 暂态（需文档澄清）> 哲学分歧（需用户决策）；对"分阶段设计"要有语境意识，不把"未实现"当 bug。

## 存疑

- 分类边界有时模糊（暂态 vs 真 bug：某"未实现"是否本该已实现，取决于阶段承诺）；
- **不可滥用"哲学分歧"回避修复**——真正的可验证缺陷须归真 bug，不能借口"分歧"拖延。

## 应用

本项目三份外部评审皆按此分诊。案例：#2 schema 字段漂移 / #3 L1 不可篡改措辞矛盾 / #7 .gitignore 锚定失效 = 真 bug；#1 py 工具不存在 / #5 PPR 无验证闭环 = 暂态；#6 自动改 SPEC 的治理模式（直改+Git vs patch+审批）= 哲学分歧（见 log-2026-09-27-02、log-2026-09-27-04）。
