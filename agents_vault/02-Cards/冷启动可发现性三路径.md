# 冷启动可发现性三路径

## 定义

新会话/冷启动 Agent 把"用户口令"映射到"工具动作"（如"做Doctor"→跑 entry_doctor）时，不依赖单一语义索引，而用三路冗余互补发现入口。

## 核心

reflect 编译自候选结晶（来源：源库日志 log-2026-09-27-06、log-2026-09-27-07、log-2026-09-28-01）：

1. **harness 引脚**（快）：内存里的轻量指针，命中即用，但易随会话漂移/过期；
2. **vault ROOT L0 常驻行**（可靠）：00-ROOT 的 ~500 token 常驻区列关键动作入口，冷启动必读、稳定不漂；
3. **权威规格**（准）：SPEC-* 是动作的最终依据（命令/参数/闸门），引脚与 L0 都指向它。

三路各占一优（快/可靠/准），冗余设计使任一路失效仍能发现动作——即"不重造语义索引、靠结构冗余保证可发现性"。可复用于未来的做Reflect、做Archive 等口令→动作映射。

## 存疑

- 三路一致性有维护成本：动作变更须同步引脚 + ROOT L0 + 规格，漏改任一路会给出过期入口（源库决策 D25 的影子记忆周期清理可部分缓解）。
