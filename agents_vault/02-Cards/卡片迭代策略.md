# 卡片迭代策略

## 定义

回答「性质各异的承重卡各自怎么迭代」：**不新增分类学**，迭代策略由 schema 既有 type 轴派生——每类卡的合法修订理由与驱动信号不同，规范写在该类宿主卡/模板内，复杂度 O(type 数) 而非 O(卡数)。

## 核心

### 问题来源（Owner 2026-11-16，引文纪律演练）

> 项目涉及不同特性性质的Cards，像针对漂移1的这种纪律卡（本质是面对低频问题的加正则策略）的迭代策略不会太复杂，但是项目Cards性质特性各异还都是承重部分

张力：单一迭代规范管不住异质卡；每卡一套规范则规范本身爆炸。解法=按 type 分派（类型是既有轴，零新分类学）。

### 派生表

| type 性质 | 合法修订理由 | 驱动信号 | 既有锚 |
|---|---|---|---|
| procedure/纪律卡 | **新偏移形态**（同形态重例不算） | 实例节累积→形态识别；条文≤7 | [[表述精确性纪律]] 迭代机制节 |
| claim/concept 承重卡 | **新证据**（证实/证伪/边界收窄） | 证据驱动 + corr + 引文块 | [[03-CHANGE-DISCIPLINE]] 引文纪律 |
| hub 枢纽 | **拓扑变化**（入度增长/再结晶-分化） | 结构驱动；B6 升迁联动提示 | [[结构性问题先查已知同构]] 存疑节 DP-4 |
| governance constraint | **Owner 裁决** | 裁决链 + corr | [[03-CHANGE-DISCIPLINE]] 既有 |

### 两条仲裁规则

1. **规范分散宿主，不集中成大规范**：每类迭代纪律写在该类宿主卡/模板内。集中式「迭代总规范」自身成为需迭代的承重文本→递归漂移风险（漂移2 机制在规范层的重演）。本卡只存派生表与仲裁规则，不复制各类细则。
2. **规范也是卡**：迭代纪律条文吃同一套结晶质量门（SPEC-WRITE 第 5 条）与引文纪律，无豁免。

### 与拓扑递归复用的关系

本卡是「喜拓扑递归复用」偏好在**时间轴**上的投影：复用既有 type 轴而非新建分类学，正如结晶复用既有枢纽而非新建孤立卡。空间复用（挂靠）+ 时间复用（类型派生）同构。

## 存疑

- seed 单源：派生表由本会话设计推导 + Owner 批，「O(type) 复杂度」论断未经多类型实践检验。
- observation/entity/summary 等 type 未列行——尚无真实迭代案例，不预填（防思辨抽象，03-CHANGE-DISCIPLINE Forbidden）；首例出现时按 corr 增行。
- 「新形态 vs 重例」判据主观，靠实例节校准（与表述纪律卡共享该边界问题）。

## 应用

修订任何承重卡前查本表定合法理由；新 type 迭代案例出现时增行（corr 留痕）。相关：[[表述精确性纪律]]（procedure 行首个实例）、[[操作注意点路由归位]]（彼治「注意点放哪」空间路由，此治「卡怎么改」时间策略）。
