# 子Agent编排纪律

## 定义

维护者/编排方给子 Agent 派任务时的五条操作纪律：任务书装载、修正时机、独立性、冷启动纯度、Agent 复用边界。是不越权纪律律 1（任务书只装目标/边界/验收）在编排场景的展开——律 1 只一句，覆盖不了时机与测试有效性维度。

## 核心

结晶自本会话两连失（来源：log-2026-11-25-17，Owner 两次纠正）：

1. **任务书只装目标/边界/验收，身份通道指 SH 不手抄**：不抄工具命令用法、不抄库内路径、不预授通道例外。身份与通道义务由子 Agent 沿 SH 指针自取——手抄即越权（[[不越权纪律]]律 1），且义务在转述中丢失（issue Guo337/sgc#4 同构）。
2. **手抄细节污染测试**：可达性/可发现性类测试中，编排方喂路径=把待测变量提前赋值，测试结果失真。实证：SH 体验任务书手抄了 SH-index 路径与 REST 用法，「入口→SH 第一跳可发现性」被迫补测。
3. **修正时机：发出前自查，跑完不追发**：任务书缺陷应在发出前对照本卡自查；已按原书跑完的任务，中途修正追溯不了污染、改变不了已发生的行为——是无效动作。正确处置：教训记入下一份任务书，不打扰现场。实证：Owner 批「不修正影响不大，修正也起不到作用」。
4. **独立性：审计/体验类不喂结论**：给审计子 Agent 的输入只有对象与问题，不带编排方倾向（三通道强隔离，见 [[独立评估与校验器独立性]]）；冷启动纯度测试须由无 prior 的 Agent 做——带多轮审计先验的 Agent 测「陌生人心智可达」打了折扣，报告须如实标注。
5. **Agent 复用边界**：同任务多轮追问用同一 Agent（保留上下文合理）；独立新任务开新 Agent，不复用旧 worker 池。

## 存疑

- 五条源自单会话两连失+一次体验报告，样本偏窄；「发出前自查」的 checklist 形态待更多编排实践校准。
- 律 3 的「跑完」判定依赖编排方对任务状态的准确感知；任务仍在跑时中途 steering 是否有效、何时值得，本卡未裁（本次实证仅覆盖已完成态）。
- 与不越权卡律 1 部分同文：本卡是编排场景展开非替代；若日后不越权卡扩写吸收本卡内容，考虑合并（contrasts_with 已隐式由 derives_from 承载）。

## 应用

维护者给子 Agent 写任务书前对照自查（尤其律 1/2/3）；派审计/评审/冷启动测试时核对律 4；决定追问还是新开时核对律 5。相关：[[不越权纪律]]（上游三律）、[[独立评估与校验器独立性]]（隔离与差分门）、[[结构性问题先查已知同构]]（时序纪律——设计类任务书必装同构检索目标项，属任务书装载清单的姊妹条）。
