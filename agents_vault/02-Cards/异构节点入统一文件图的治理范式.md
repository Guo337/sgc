# 异构节点入统一文件图的治理范式（脚本卷实证）

## 定义

当**非知识本体**（可执行程序、配置、数据文件等）要进入一个以知识条目为原型的统一文件治理图（frontmatter 身份 + 链接 + 校验 + 来源链）时，如何**复用治理经验而不套用知识假设**的可迁移范式。TTL 实证：8 个 runtime 脚本卷化（.md 成源、.py 降为用时抽取的产物），Unix「一切皆文件」同构评估 + 三张力裁决（2026-11-16，TTL-SCRIPT-VOLUME-PLAN §1/§2，Owner 逐项裁毕）。

## 核心

### 三张力（范式的心脏，Owner 裁「务必严格贯彻」）

1. **载体统一 ≠ 可信**：「一切皆文件」只解决*接入*（统一索引/链接/工具接口），不解决*可信*。异构节点必须再叠专属治理（校验判据 + 来源链 + 连通契约），不能「皆文件」就放行。
2. **接口统一 ≠ 本体统一**：统一接口易诱发「顺手套知识卡模子」的物化诱惑。程序不是知识：不套 layer/project/domain/maturity/summary/k-v-e 边/append-only 正文——这些是*知识语义假设*，强套即物化。可复用的是*治理结构*（身份唯一、type 声明异构本体、来源版本链、指针非副本、可达性按 type 定制）。
3. **文件无内建来源/不可篡改语义**：普通文件可覆盖无痕；入图节点必须继承来源纪律（内容哈希 + Git 版本权威 + 演进留痕），不是「放进目录就算治理了」。

### 身份锚定：参照该本体在原生世界的身份习惯

程序世界的脚本身份是三件套，**没有「按创建日期编序号」的习惯**：

| 身份层 | 程序世界对应 | 卷承载 |
|---|---|---|
| 调用身份 | 脚本路径 = 命令名（稳定/人可读/可 grep） | 文件名 + `source-of` 抽取落点路径 |
| 治理身份 | 包注册名 / import 名（稳定把手） | `id: vol-{program}`（程序名派生，重命名=换 id 走更正） |
| 完整性身份 | pip lock / go.sum 内容哈希 | `sha256` + Git 权威 |

日期序号（`vol-2026-00001`）是知识条目的治理习惯，套到脚本上=身份与程序名脱钩、引用须查表——被否决。**通用律：异构节点的身份设计先问「它在原生世界怎么被标识」，再叠治理层**；路径层级（stem 非全局唯一）预先定死撞名规则（后来者加目录段限定，先来者不动，同包命名空间），不留「届时再议」。

### 豁免必配替代判据（G 原理的异构应用）

豁免知识必填字段不是放行，是**换判据**：VOL_FM（技术字段齐 + id↔文件名↔source-of 三同源）/ VOL_FENCE（恰一个完整代码围栏）/ VOL_SHA256（实算哈希==声明）。且豁免是**双向封闭世界**：卷豁免知识判据，也不得穿戴知识字段（VOL_KNOWLEDGE_FIELD）——否则类别边界被穿透。适用性由引擎按类别集中分发，不靠各规则体内临时守卫（v2.7.0 RC4 教训）。

### 真值单份，不镜像

版本真值 = 代码内 `VERSION` 常量（G20 锚点对账）；frontmatter **不镜像版本号**——双份必漂移（反物化）。哈希是自证锚不是外部锚（能改库者能改卷并重算 sha），外部信任根仍是 git + Owner（见 [[自指信任根与TCB最小化]]）。

### 产物不物化

.py 是**用时抽取的产物**（gitignore，无常驻文件）：二进制切片抽取 → 比 sha → 运行 → 删。「源」只有一份（卷内代码块），产物可随时重建——表征不等于事物本身，常驻产物=第二份手抄源。自举配方约 10 行，Agent 在场即能跑，无需第三方依赖。

## 存疑

- **单本体实证**：范式从「程序入知识图」提炼；配置/数据/二进制资产入图是否同样三张力成立，未实证（推导自信：张力源于「统一接口 vs 异构本体」的一般矛盾，非程序特有）。
- **磁盘暂态无执行者**：「产物用完即删」靠纪律 + gitignore，无机械校验（doctor 自身运行时 .py 临时存在会误报，故不设 VOL_NO_PY）——Owner 裁维持的接受风险。**首次活体触发（G23）**：编排方结晶本卡后跑闸门即跳步未删，实证「写进文档≠已经治理」的自指陷阱；义务文本此前亦缺位（仅注释/存疑节），corr-56 补 SPEC-GOVERN 动作指令。详见 [[EFG三原理]] E 原理两级失效 + 自指陷阱节。
- **SH 枢纽泛化未实施**：「枢纽结构」与「知识域语义」可分离已获方向批准，但运行时枢纽（收录卷、服务操作意图）单点暂不立——避免为单点造结构；推广后再议。

## 应用

任何「把 X 纳入统一治理图」的设计（程序/配置/数据集/外部资产入知识库、monorepo 异构包统一 CI、文档系统收录非文档节点）先过三张力自检，再按「原生身份习惯 → 治理把手 → 完整性锚」三层设计身份，豁免处立替代判据。实证链：TTL-SCRIPT-MD-MIGRATION-PLAN（试点）→ TTL-SCRIPT-VOLUME-PLAN（契约与拓扑，V1~V5）→ corr-2026-11-16-48/51（schema/依赖图）→ v2.7.0 类别分治（corr-2026-11-16-55）。操作细节以 [[副库建库引导]] 第 2 步与 SPEC-GOVERN §doctor 为准，本卡只讲范式。
