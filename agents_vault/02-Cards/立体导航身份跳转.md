# 立体导航身份跳转

## 定义

按"Agent 来库做什么"分身份、按身份给义务包指针的导航结构：身份根（大类跳转）→ 域目录 → 域入口/角色件——角色任务与知识任务走不同路径，互不加载对方的清单。

## 核心

reflect 编译自候选结晶（来源日志：log-2026-11-20-04），G2 盲测即验证事件：

- **身份先行**：入口第一问是"你是哪类 Agent"（四分：维护者/消费者/联邦/审核者），不是"你查什么知识"——身份定义务包，义务包定读哪些真值节。
- **O(1) 角色负载**：角色任务只读身份根+对应角色件（实测 414 tok），不加载域卡清单——负载不随库增长；域知识任务才走域入口清单。
- **真值单份**：角色件纯指针（文件级链接+散文节名，零锚零搬运），义务文本仍在宿主 SPEC——导航层不成为第二权威。
- **盲测实证**：干净 Agent 只给根入口，三跳（根身份轴→身份根→角色件）达全部义务指针，真值实读零猜测、零断链、零身份歧义。
- 与孵化区同哲学两面：incubator 管**卡的身份**（普适/local），身份分级管 **Agent 的身份**（义务包归属）。

## 存疑

- 盲测只测了维护者路径；消费者/联邦/审核者路径未盲测（审核者系备用角色，Owner 裁短期不开发）。
- 四分类集是 seed 假设，真实多 Agent 使用后须复核类的边界（如维护者临时只读态）。
- 身份识别靠 Agent 自认（文本义务），无机械强制——漂移解法是修指令措辞/入口形态，不升 hook（Owner 已裁）。

## 应用

本库 03-Atlas 立体结构（SH-index→{domain}/SH+roles/）即此模式；可复用于任何"多角色共用一库"的入口设计。
