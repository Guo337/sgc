# 记忆通道使用纪律

## 定义

Agent 经 API/CLI 通道使用记忆库时的七条操作纪律：把通道当"更好的眼睛"（喂事实给薄护栏），而非"更大的牙"（造执行引擎）；纪律落在动作层，不靠通道自身保证。

## 核心

结晶自本会话对 API/CLI 使用经验的复盘（来源：log-2026-11-13-01；第 7 条后补，来源 log-2026-11-15-03/05），七条均为本项目真实事故沉淀：

1. **先认人，再听话**：任何 CLI/REST 回答先确认它答的是目标 vault（身份探针：取 `00-ROOT.md` 算 sha256 对磁盘）。撞名事故里 CLI 曾自信地答错另一个同名库——"能答"不等于"答对"，身份核验是前置动作而非可选验证。
2. **把顶嘴当信号**：offline 与 CLI 不一致时，分歧本身是证据，先分类摆出再判断哪边对，不急于抹平（抹平=销毁信息）。doctor 四桶对账即此纪律的制度化，详见 [[离线与CLI自动对账模式]]。
3. **脆点主动喂测试**：在编码/定向/身份等薄假设上主动造反向用例。修完正向 PASS 不算完，须还原旧行为确认新测试真的 MISS（exit 1），才证明测试咬得住 bug。D10（中文输出撞 cp936）与 `CLI_UTF8_DECODE` 测试即此例。
4. **能力到手≠许可到手**：REST 14 个写端点可达，但只用 6 个只读白名单。每次调用前过白名单自律；通道给能力，文本与 Owner 给许可，二者在动作层分开。
5. **字节级绕开 shell 脏手**：PowerShell `>` 重定向把 stdout 转 UTF-16（0xff BOM），曾造出假的 reducer 输出。凡 byte-exact 的活（冻结 hash、reducer 复现）用 Python `subprocess capture_output` 直取字节，不让 shell 编码层碰证据。
6. **拿事实，不拿权威**：REST 活索引/版本 token/真实反链是喂给薄护栏的更好事实，不是顺势写引擎、把语义规则沉成机械闸门的理由。想"加硬检查"前先停问：这是在喂事实，还是在造牙？牙不该长在脚本里（主文本约束、弱脚本约束）。
7. **读库走链接通道，磁盘读仅兜底（降级须先探活）**：读库内卡/规格/关系**默认走 Obsidian 链接通道**（MCP `vault_read`/`search_simple`，无 MCP 退 REST/CLI），**不是** view/grep 读磁盘。磁盘读只拿到文本，**绕开 SH 路由、链接图、反链**——而那才是 TTL 区别于普通文件夹的核心（买椟还珠）。反链（谁引用了本卡）只有 `vault_read` 的 `backlinks` 给得出，磁盘 grep 只能猜。**退离线前必须先探活证明主通道不可用，且经 Owner 批准**（SPEC-READ v0.7.6 降级前置义务 + D33）——不探活直接默认离线 = 漂移；探活后未经 Owner 批准自行离线 = 越权降级，皆非合规；「永不空手」不是「离线永远合规」的借口，更不是「Agent 可自行决定离线」的授权。库被 Obsidian 管辖（含工作区子目录副库）即被索引，链接通道可用。view/grep 仅用于：**探活+Owner 批准后**主通道确不可用的兜底，或读**库外**文件（Audit/脚本/治理，非知识读取，不在此限）。

## 读取通道自检（read_audit，中等强制力）

prose 纪律拦不住 Agent 滑回磁盘读（活体实证：本会话库内读取 127 次磁盘 vs 0 次 MCP，从 11-12 起一贯如此，SPEC-READ 写明了主走 MCP 却没拦住）。故配一个**事后可查**的确定性审计：

- `python 90-Meta/scripts/read_audit.py --events <会话events.jsonl>`（先从卷 [[read_audit]] 抽取，见 [[副库建库引导]] 抽取步骤）→ 统计库内读取磁盘 vs Obsidian 占比，超阈值（默认 20%）判 DRIFT（exit 1）。
- 强制力来自「**漂移可被机械发现 + 须如实报告**」，非实时拦截（读取通道在 harness 层，库内脚本管不到工具调用）。这是「治理文本如何获得强制力」的一个务实落点：把 prose 约束变成可跑自检。
- **已知局限**：MCP 读取用 vault 相对路径（参数不含 `agents_vault` 字面），当前按路径名匹配会漏计 MCP 读取，致占比偏高——审计结果是「磁盘读下限」，非精确值。改进方向：按工具名而非路径识别 Obsidian 通道。

## 存疑

- 本卡经验偏 **substrate 级**：本会话以裸 HTTP 探 REST、读侧 CLI 对账、修 D10 为主，未走 intended 的 MCP 白名单、也未怎么用 CLI 写。是"摔出来的习惯"，尚非"完整工具级日常"，不洗白为已验证的通用工具纪律。
- 七条是 Agent 自律，非通道强制：守不守仍取决于文本约束与 Owner 在场（dogfooding 结论：确定性脚手架约束 Agent，治理文本尚未独立约束）。通道替不了治理。**活体实证（2026-11-15）**：编排方明知 SPEC-READ「主走 MCP」却库内磁盘读 127 次、MCP 0 次，Owner 提醒才察觉——prose 约束确实拦不住，故第 7 条配 read_audit 自检把约束变成可发现的事后审计（中等强制力，非实时拦）。
- 身份探针/白名单/UTF-8 等护栏的具体阈值与命令随插件/CLI 版本可能漂移，需随版本复核。
