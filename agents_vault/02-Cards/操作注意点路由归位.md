# 操作注意点路由归位

## 定义

记忆系统自维护纪律：把每条"操作注意点"按性质**路由到正确的系统载体**固化下来，而非依赖用户反复口头提醒或滞留于上下文（会随会话压缩丢失）。

## 核心

reflect 编译自候选结晶（来源日志：log-2026-09-28-01）：

| 注意点性质 | 归位载体 | 触达方式 |
|---|---|---|
| 项目约定 / 规范 | L3 规格（SPEC-*，`trigger: always`/`on-domain`） | 冷启动读 ROOT → 规格即得 |
| 坑 / 踩坑教训 | L3 pitfall 卡（PIT-*，触发式） | 命中域/文件模式时浮现 |
| 通用可复用准则 | harness 引脚（指针，不含知识本体） | 语义命中即用 |
| 知识本体 | vault 卡片 / spec（D18：不留私货） | 结构导航 + 检索 |

判据承接 [[私有记忆迁移入库操作纪律]] 与 [[PIT-私有记忆与引脚混淆]]："指向知识"→引脚；"就是知识"→迁 vault。与"冷启动可发现性三路径"互补（后者管发现，本卡管归位）。

## 存疑

- 路由边界有时模糊（"通用准则" vs "项目约定"）：如评审分诊三层法既像通用方法论又带项目案例，须个案判定（见 m2）。
- 须**周期审计**防止注意点滞留在口头/上下文而未归位。

## 应用

本轮皆按此路由：daf9e352 脚本注释规范→SPEC-GOVERN §工具脚本规范；提交节奏→SPEC-GOVERN v0.7；坑A/坑B/校验集分离等→PIT 卡；幂等守卫/记忆迁移纪律→L2 procedure 卡。
