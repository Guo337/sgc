# 上提验收流程（副库 → 主库，联邦机制 3）

## 定义

副库把普适经验上提主库、主库验收并入的可走流程。是 [[SPEC-GOVERN]]「贡献→审核→并入」的**跨库版**——复用申报报告/审核角色/角色分离/Owner 终审，只加跨库层（id 换算/来源指针/普适性审查）。首次端到端实证：vplc-001（2026-11-15，并入 2 卡留 1 卡）。

## 核心

### 角色分离（产出者 ≠ 验收者）

副库 Agent = 产出者（写卡 + 申报报告）；主库 Agent = 验收者（复核 + 并入）；Owner = 终审（重大/普适性争议）。打破自出自审（EFG 的 F）。

### 六步

1. **普适性自查（产出者）**：逐张问「换个无关项目还管用吗？」。管用（一般机制）→ 候选；只管本项目（实例全绑项目）→ 留副库。**宁可少提**。一般内核普适但实例全绑项目的，建议主库去实例化重写而非直接并入。
   - **主题归属判据（Owner 2026-11-22 补，corr-98）**：普适性 ≠ 主题归属。卡入主库不仅看方法是否普适，还须看**主题是否属于本库核心论域（记忆治理/知识工程）**。外部工具技能卡（如出版方反爬抓取、文献下载技巧）方法再普适，主题也不属本库论域 → **留副库，不上提**。判据：去掉项目专名后，卡的*主题*（非方法）是否仍是「AI 记忆/知识如何被治理到可信」？是→候选；否（如「如何绕过出版方反爬」）→留副库。诱因：c-2026-00021《出版方抓取环境踩坑》误以「分诊方法普适」并入知识工程域，与治理卡同域并列，Owner 裁剔除归位副库。**方法普适是必要条件，主题归属是充分条件，两者皆须**。
2. **inbox 交件（产出者）**：导出到主库 `90-Meta/inbox/<submission-id>/`——每张卡一文件（保留副库 id + 跨库来源指针）+ 一份 REPORT.md（T-report 结构 + **普适性论证** + 冲突自查 + 建议边）。只写该子目录，不碰主库其他文件。报告一经提交不可篡改。
3. **MCP 验收（验收者，5 标准）**：走链接通道读交件 + 查主库相邻卡反链/内容核实冲突——① **普适性 + 主题归属**（核心，换项目检验 + 主题属本库论域；外部工具技能卡即使方法普适也退回留副库，corr-98）② 结构合规（frontmatter/边/summary/存疑不洗白）③ 来源可核（跨库指针）④ 不冲突（重复则合并/互引，非 supersedes）⑤ id 不撞（**换号后**不撞主库既有/保留号段；副库前缀撞车也在此边界拦——两副库同前缀只在都上提时暴露，无需中央注册，schema id_namespace）。
4. **Owner 终审**：验收裁决（并入/退回/留副库 + 边重接方案）属重大裁决，归 Owner。
5. **并入（验收者）**：换主库 id 序列（接当前最大 c-2026-xxxxx；副库新卡带 `{kind}-{slug}-…` 前缀，schema id_namespace——**移交换号**，Jira move issue / GitHub 跨仓引用同构），project 改 memory-lib，provenance 记 feedback + 跨库来源（副库原 id + 源日志 + 库外 KB），**边重接主库 Atlas/卡**（副库 SH 主库无，须改指）；删与主库重复条改互引；SH 加导航行。
6. **归档（验收者）**：inbox 交件 → `Audit/Current/upstream-archive/<submission-id>/`（审计痕迹保留，inbox 清空）。**必须移出 Obsidian 索引**——否则交件残留副库链接污染 `--use-cli` 对账（实测：inbox 被 doctor 离线 HARD_SKIP 但 Obsidian 索引含它，对账报假 WARN）。

### 验证

并入后 `entry_doctor --use-cli`（App 在跑）对账四项应全无、0E；归档后重载 vault 复跑确认 inbox 断链 WARN 消失。冻结件不碰。

## 存疑

- **单次端到端样本**（vplc-001）：流程是否够更多副库/更复杂普适性争议用，待后续检验。**主题归属误判实证**：vplc-001 并入的 c-2026-00021《出版方抓取环境踩坑》于 2026-11-22 Owner 裁剔除归位副库（corr-98）——当时只判「分诊方法普适」未判主题归属，致外部技能卡误入治理域；据此补主题归属判据（第1步+验收①）。首次实证净并入由 2 卡修正为 1 卡（c-2026-00020 证据分级卡保留，因其与 EFG-F/外部评审有治理关联）。
- **普适性审查是主观判断**：产出者自判 + 验收者复核 + Owner 终审三层，但无机械判据（普适性难量化）；争议归 Owner。
- **inbox 索引污染**：已确立「验收后归档移出索引」流程，但若验收中途 App 索引滞后，对账可能短暂报假 WARN（重载即消）。
- **跨库反链不原生**：来源指针是显式文本（副库路径 + id），非 Obsidian 跨库反链（不存在）；回溯须按指针手动跳副库。

## 应用

副库 Agent 上提普适经验、主库 Agent 验收并入时照此流程。与 [[副库建库引导]]（建库腿）配套成联邦完整链路（建库→运转→上提）。实证见 log-2026-11-15-04；架构背景 `Audit/Current/TTL-FEDERATION-ARCHITECTURE-DRAFT.md`（NON-AUTHORITY）。
