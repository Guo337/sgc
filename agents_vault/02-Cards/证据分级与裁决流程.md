# 证据分级与裁决流程

## 定义

文献调研/技术选型/竞品分析中防止"检索摘要冒充已读证据"的分级纪律：每条事实性陈述带核实标签，空档（gap）主张必须由最近邻论文的**全文**裁决，摘要级证据只能当线索。

## 核心

1. **三级标签**：✅ 已核实原文（全文/官方文档原文）/ 🔍 检索佐证（题录+摘要+多源交叉）/ ⏳ 待核实。**⏳ 与 🔍 不得支撑结论**，只能支撑"下一步去读什么"。
2. **摘要会误导**：源项目实例——L8（Monaco ISORC 2023）检索摘要含"PoC controller"字样，据此曾把它记为"有原型实现"；全文读后确认**纯架构提案、零实现零实验**（结论原话 "Future steps involve completing the implementation"）。一个摘要词差点污染空档判断。
3. **空档主张的裁决流程**：主张"X 无人做"之前，列出最近邻论文清单 → 逐篇取全文 → 逐篇确认"它做了什么/没做什么" → 全部确认未覆盖才成立。源项目 G3 空档由 L17/L30/L32/L26/L11 五篇全文裁决完毕才敢写"成立"。
4. **厂商宣称与实测分轨**：厂商自测数字（如 Foxboro SDA 的 100ms/600ms）只能用于产业现状判断，不得用于技术结论；引用时必须带"厂商自测"标注。
5. **裁决要写进证据登记处**：每篇全文读完后，把"占据什么/未占据什么"写回矩阵行，空档文档同步从 ⏳ 改 ✅——裁决不留痕等于没裁决。

## 存疑

- 全文获取受出版方访问限制（反爬/网络层封锁须分诊，OA API 先行+下载验完整性+人工分工；该抓取技能属外部工具技能，非本库治理论域，原卡 c-2026-00021 已 Owner 裁剔除归位副库，见 corr-2026-11-22-98），部分最近邻只能停在摘要级——此时空档主张必须显式标注"以某篇全文确认为前提"，不得默认为已裁决。

## 应用

任何文献调研/技术选型/竞品分析的证据登记处（矩阵/空档文档/综述）按此纪律运转；新空档主张先走裁决流程。与 [[外部评审三层分诊法]] 上游互补（本卡管证据产出前的分级裁决，该卡管收到评审后的分类处置）；与 [[EFG三原理]] 的 F（独立裁判）精神一致。
